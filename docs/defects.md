# Defects - jupyterlab_kimi_code_extension

`[ ]` open, `[x]` fixed. Dated notes under each track how it evolved.

## Fork

- [ ] `DEF-1` **fork-by-copy coupled to kimi 0.31.0 session-dir format** - LOW; fork_session copies `session_<uuid>/` and appends `session_index.jsonl`, both internal layouts; cause: kimi has no fork CLI flag so the extension owns fork mechanics; fix: re-verify against live `~/.kimi-code` on every kimi upgrade, adapt `fork_session` when the layout moves; `jupyterlab_kimi_code_extension/sessions.py`
  - 2026-07-31 reported: design risk recorded at implementation time (verified against kimi 0.31.0), see [acc-crit Documented Deviations](acc-crit-jupyterlab_kimi_code_extension.md#documented-deviations)

## Server

- [x] `DEF-2` **untitled branch labels all rendered as the constant 'session\_'** - list_branches fallback label truncated session_<uuid> to its first 8 chars which is always the literal prefix; cause: reference used 8-char claude uuids, kimi ids carry a session_ prefix; fix: label from uuid part name[8:16]; `jupyterlab_kimi_code_extension/sessions.py`
  - 2026-07-31 reported: found by pytest port agent during suite authoring
  - 2026-07-31 fixed: fixed: name[8:16] fallback, pinned by test_list_branches_untitled_label_is_short_uuid, 144 pytest green
- [x] `DEF-3` **fork endpoint accepted unknown body keys** - SessionForkHandler ignored extras while launch-terminal rejects them; cause: _ALLOWED_KEYS gate only ported to launch handler; fix: same gate on fork; `jupyterlab_kimi_code_extension/routes.py`
  - 2026-07-31 reported: found by pytest port agent during suite authoring
  - 2026-07-31 fixed: fixed: _ALLOWED_KEYS gate on fork, pinned by test_fork_endpoint_rejects_unknown_keys, 144 pytest green

## Panel

- [x] `DEF-4` **frontend short ids rendered the constant 'session\_' prefix** - branch submenu and Manage Sessions current-row sliced session_id from the front; cause: frontend twin of DEF-2, claude ids were bare uuids; fix: _shortSessionId helper slicing the uuid part (8,16); `src/widget.ts`
  - 2026-07-31 reported: found by Galata port agent during ui-test authoring
  - 2026-07-31 fixed: fixed: _shortSessionId helper, pinned by jest short-id contract test, 51 jest green + tsc clean
- [ ] `DEF-5` **message-count cache never evicts entries for deleted sessions** - LOW; _message_count_cache keys survive delete_branches/cleanup/remove, so a long-lived server retains one small tuple per wire file ever seen; cause: cache added in round-1 review to stop re-scanning multi-MB transcripts every 30s poll; fix: declined - keys are uuid4 paths that never recur and cannot alias, pruning means touching three delete paths for tens of bytes; `jupyterlab_kimi_code_extension/sessions.py`
  - 2026-07-31 reported: raised by round-2 adversarial review (slop-hunter, ux-designer); declined as machinery exceeding the defect
- [ ] `DEF-6` **each session row is its own tab stop** - LOW; all three sections expand by default and one project appears in Favorites, Recent and All, so a large list costs many Tab presses and announces the same name three times; cause: round-1 accessibility fix made every row focusable; fix: deferred - APG roving-tabindex with Up/Down navigation is the correct pattern but is a new interaction model, not a review remedy; `src/widget.ts`
  - 2026-07-31 reported: raised by round-2 adversarial review (ux-designer); deferred to a dedicated accessibility pass
- [x] `DEF-7` **mouseleave flush re-rendered the list under an open context menu** - MAJOR; the poll tick guards on `_contextMenu.isAttached` but the round-2 flush handler did not, and opening a Lumino menu at the cursor fires `mouseleave` with no pointer movement, so the deferred tick fired and rebuilt the rows the menu was acting on; cause: the round-2 hover-deferral remedy added a second refresh path without mirroring the first path's guard; fix: guard the flush on `_contextMenu.isAttached` and leave `_pendingRefresh` set so the next leave or tick still delivers it; `src/widget.ts`
  - 2026-08-01 reported: raised unanimously by round-3 adversarial review (architect, bug-hunter, ux-designer, slop-hunter); bug-hunter confirmed the no-movement `mouseleave` empirically in chromium
  - 2026-08-01 fixed: guard added, pinned by jest `the mouseleave flush mirrors the poll context-menu guard`, 68 jest green
- [x] `DEF-8` **hover deferral froze the list for as long as the pointer was parked** - MAJOR; `_startPolling` deferred on every tick while `_bodyEl` was `:hover`, and only `mouseleave` flushed, so a cursor left over the sidebar while the user worked in the terminal stopped all refreshes indefinitely; the code comment claimed the opposite ("delays the refresh rather than freezing the list"); cause: round-2 remedy for a round-1 hover bug traded one freeze for another; fix: bound the deferral to a single tick via `&& !this._pendingRefresh`, capping staleness at 2x `POLL_INTERVAL_MS`, and correct the comment; `src/widget.ts`
  - 2026-08-01 reported: raised by round-3 architect; bug-hunter and ux-designer both cleared this item, having assumed the pointer eventually leaves - the architect's parked-cursor case is the one that holds
  - 2026-08-01 fixed: one-tick bound, pinned by jest `deferred at most one tick`, 68 jest green
- [x] `DEF-9` **section-header focus destroyed on every collapse and expand** - MAJOR; the round-2 focus restore matched `.jp-KimiSessionsPanel-row` only, but the section header is a `<button>` inside `_bodyEl` whose own click handler calls `_render()`, so a keyboard user pressing Enter on a header lost focus to `<body>` and the next Tab restarted at the top of the document; unlike the poll-tick case the remedy targeted, this fired on 100% of toggles; cause: the remedy fixed the incidental focus loss and left the deliberate one; fix: stamp `header.dataset.rowKey = key` and widen capture/restore to `[data-row-key]`, covering both focusables; `src/widget.ts`
  - 2026-08-01 reported: raised by all four round-3 reviewers
  - 2026-08-01 fixed: pinned by jest `focus restore covers section headers, not only rows`, 68 jest green
- [x] `DEF-10` **a successful cleanup reported "Cleanup failed"** - MAJOR; `await this._fetch()` sat inside the same `try` as the cleanup POST, so a failed follow-up `GET sessions` landed in the catch and overwrote "Removed N parallel sessions." with an error, while the sessions really had been trashed; round-2 item 5 had made that inline message the sole user-facing surface, so nothing contradicted it; cause: refresh and reported operation shared one try block; fix: self-catch the refresh; `src/widget.ts`
  - 2026-08-01 reported: raised by round-3 bug-hunter
  - 2026-08-01 fixed: pinned by jest `self-catches the success refresh`, 68 jest green
- [x] `DEF-11` **a successful branch delete was swallowed when its refresh failed** - MAJOR; `_deleteBranches` ran `await this._fetch()` in `finally`, and a throw inside `finally` overrides the `try`'s `return`, so the whole call rejected after a successful delete - no "N deleted" status, no screen-reader announcement, deleted rows left on screen, and a second click then reported "0 deleted"; cause: `finally` used for the refresh without the self-catch `_switchBranch` already had; fix: `.catch(() => undefined)`; `src/widget.ts`
  - 2026-08-01 reported: raised by round-3 bug-hunter
  - 2026-08-01 fixed: pinned by the tightened jest `delete posts to sessions/delete-branches and resyncs the panel`, 68 jest green
- [ ] `DEF-12` **reduced-motion cleanup bar reads as "0% complete"** - LOW; under `prefers-reduced-motion` the cleanup progress bar is made determinate at `value = 0` and stays there for the whole in-flight POST, which reads as a progress claim the code cannot support; cause: round-2 remedy replaced a UA-animated indeterminate bar that author CSS cannot stop; fix: declined - the proposed remedy (drop the bar entirely) also leaves no activity cue, so it trades one imperfect signal for none; the message text carries the state either way; `src/widget.ts`
  - 2026-08-01 reported: raised by round-3 ux-designer; bug-hunter and architect both rated the same item correct
- [ ] `DEF-13` **focus lost when a row moves between sections** - LOW; the three-part focus key is section-scoped by design, so un-favouriting a focused row, or a poll re-sort pushing it out of Recent, leaves no key match and focus falls to `<body>`; cause: deliberate anti-teleport design - a bare `encoded_path + session_id` key would re-focus the first match and move the user between sections; fix: declined - the architect's own assessment is that declining is defensible since this is an incomplete win rather than a regression; a cross-section fallback would reintroduce the teleport it was designed to prevent; `src/widget.ts`
  - 2026-08-01 reported: raised by round-3 architect and ux-designer
- [ ] `DEF-14` **a control character in the kimi-dir path writes an unparseable tui.toml** - LOW; `_merge_status_line` escapes backslash and double quote but not control characters, so a directory name containing a literal newline produces a TOML file kimi cannot load at all; cause: escaping added in round 2 covered the two characters that occur in practice; fix: declined - reachable only via `--kimi-dir` pointing at a path with an embedded newline, and the line-based merge would corrupt on the same input; three of four reviewers independently recommended leaving it; `jupyterlab_kimi_code_extension/cli.py`
  - 2026-08-01 reported: raised by round-3 slop-hunter, who also verified every realistic metacharacter round-trips correctly
